# Contributing

The manifesto is open to pull requests. Thank you for helping make it better.

## What we're looking for

| Contribution | How |
|---|---|
| Typo, broken link, clearer wording in a guide | Open a PR directly |
| A practical check or question for a principle | PR to the file in `principles/` |
| <a id="add-a-story"></a>**A story** that illustrates a principle | Add a file to `stories/` (see below) |
| A translation | Add `translations/<lang>/MANIFESTO.md` (e.g. `ro`, `ru`) |
| Changing the wording of a principle, or adding/removing one | **Open an issue first** |
| Signing the manifesto | Add one line to `SIGNATORIES.md` |

## Adding a story
1. Copy the shape of [stories/zero-annulments.md](stories/zero-annulments.md): what happened, the turn, what you took from it.
2. Link the principles it illustrates at the top.
3. **Anonymise.** No client names, colleague names, internal system names or confidential figures.
4. Keep it under about 400 words.

## Style
- Plain language. Write for a developer, a manager and someone who has never heard of EIM.
- Short sentences. Concrete examples over abstractions.
- British spelling (organisation, contextualised).

## Changing the principles
The six principles are deliberately few. Proposals to change them are welcome, but please
open an issue explaining the problem the change solves and an example where the current
wording falls short. Security and privacy are deliberately out of scope: they matter
enormously, and they have their own frameworks.

## Code of conduct
Be kind, be specific, assume good intent. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
